### 🖥️ Screen 1 : 여행지 검색 페이지

#### 3-1. 초안 프롬프트

**초안 이미지 프롬프트**

모바일 여행 예약 앱의 “여행지 검색” 화면을 제작한다.

※ 스마트폰 기기 프레임, 노치, 상태표시줄 없이 세로형 모바일 앱의 순수 UI 스크린샷 형태로 제작한다.

[전체 무드]  
깔끔하고 신뢰감 있는 프리미엄 여행 예약 서비스. 짙은 네이비를 메인 컬러로 사용하고, 활성화된 요소는 선명한 블루, 예약 CTA 버튼은 코랄·오렌지 레드 계열을 사용한다. 전체적으로 둥근 모서리와 화이트 카드 기반의 현대적인 모바일 UI를 적용한다.

[상단 영역]  
상단 중앙에 “여행지 검색” 제목. 좌측에는 뒤로가기 아이콘을 배치한다. 그 아래에 가로로 긴 흰색 검색창을 배치하고, 좌측 검색 아이콘과 검색어 “도쿄”, 우측에는 입력 내용을 삭제하는 X 아이콘을 넣는다.

[카테고리 영역]  
검색창 아래에 항공권 / 호텔 / 명소 3개의 필터 버튼을 가로로 배치한다.  
- 항공권: 선택 상태, 블루 배경 + 화이트 비행기 아이콘과 텍스트  
- 호텔: 네이비 배경 위 밝은 아웃라인  
- 명소: 네이비 배경 위 밝은 아웃라인

[검색 결과 카드]

**초안 문제점 분석**

- 여행 상품별 정보가 많아 카드 내부의 정보 위계가 흐려질 가능성이 있음.
- 가격과 예약 버튼이 상품 정보보다 더 강하게 보이도록 시각적 우선순위를 조정할 필요가 있음.
- 여행지 사진의 색감이 제각각이면 전체 화면의 통일성이 약해질 수 있음.
- 하단 네비게이션과 검색 결과 영역 사이의 간격이 부족하면 마지막 카드가 답답하게 보일 수 있음.

#### 3-2. 수정 프롬프트

**수정 이미지 프롬프트**

기존 여행지 검색 화면의 전체 구성과 정보는 그대로 유지한다. 다른 부분은 임의로 변경하지 않는다.

다음 사항만 수정한다.

1. 네이비 배경을 더 깊고 선명하게 만들어 흰색 카드와 명확하게 대비되도록 한다.
2. 각 상품 카드의 가격은 우측에 큰 굵은 글씨로 배치하여 가장 먼저 인식되도록 한다.
3. “예약하기” 버튼은 코랄 레드 계열의 둥근 직사각형으로 통일한다.
4. 상품명은 카드에서 가장 굵은 텍스트로 표현하고 일정·항공·호텔 정보는 한 단계 작은 크기로 통일한다.
5. 평점 앞에는 블루 별 아이콘을 배치한다.
6. 카드 이미지 크기와 모서리 반경을 모두 동일하게 맞춘다.
7. 마지막 상품 카드와 하단 네비게이션이 겹치지 않도록 충분한 하단 여백을 확보한다.

**수정 이유**

초안에서 가장 중요한 사용자 행동은 상품을 비교한 뒤 예약 버튼을 누르는 것이므로 가격과 CTA의 시각적 우선순위를 강화하였다. 또한 세 상품의 이미지·카드 규격을 동일하게 맞춰 반복되는 리스트 UI의 일관성을 높였다.

#### 3-3. 최종 프롬프트

**최종 선택 이유**

수정본은 검색어, 카테고리 필터, 상품 이미지, 일정, 항공사, 호텔 등급, 평점, 가격, 예약 버튼까지 한 화면에서 자연스럽게 비교할 수 있다. 네이비 배경과 화이트 카드의 대비가 명확하고, 블루 활성 상태와 코랄 CTA가 분리되어 사용자가 현재 위치와 다음 행동을 빠르게 이해할 수 있으므로 최종안으로 선택하였다.

**최종 화면 기준**

- 상단 제목: 여행지 검색
- 검색어: 도쿄
- 활성 카테고리: 항공권
- 검색 결과: 도쿄 3일 / 도쿄 4일 / 도쿄 5일
- 하단 활성 탭: 검색

### 🖥️ Screen 2 : 여행 상품 검색 결과

#### 3-1. 초안 프롬프트

**초안 이미지 프롬프트**

Screen 1과 동일한 디자인 시스템을 유지한 여행 상품 검색 결과 화면을 제작한다.

도쿄 여행 상품 3개를 카드 형태로 세로 배치한다. 상품마다 실제 여행지 사진을 크게 노출하고, 우측에는 상품명·일정·항공사·호텔 등급·평점·가격·예약하기 버튼을 배치한다.

전체 화면은 네이비 배경과 화이트 카드, 블루 포인트, 코랄 예약 버튼을 사용한다. 카드의 모서리는 충분히 둥글게 하고 상품 사이에 일정한 간격을 둔다.

첫 상품에는 “인기”, 두 번째 상품에는 “추천” 배지를 사용하여 상품의 특징을 표시한다.

**초안 문제점 분석**

- 상품 3개의 정보 구조가 조금이라도 달라지면 사용자가 비교하기 어려움.
- 배지 위치가 상품마다 다르면 카드 정렬이 어색해질 수 있음.
- 여행지 이미지의 비율이 달라지면 전체 리스트가 불규칙해 보일 수 있음.
- 가격 단위와 ‘1인 기준’ 표기가 명확해야 함.

#### 3-2. 수정 프롬프트

**수정 이미지 프롬프트**

모든 상품 카드는 동일한 크기와 동일한 정보 순서를 유지한다.

정보 순서는 반드시 다음과 같이 한다.

`배지 → 상품명 → 여행 일정 → 항공사·호텔 → 구분선 → 평점 → 가격 → 예약하기`

가격 위에는 작은 글씨로 “1인 기준”을 표시한다.  
가격은 `699,000원`, `799,000원`, `899,000원`으로 정확하게 표기한다.

첫 번째 상품은 도쿄 스카이트리와 벚꽃 이미지, 두 번째 상품은 일본 전통 사찰 이미지, 세 번째 상품은 시부야 도심 이미지로 구성한다.

다른 색상, 텍스트, 하단 네비게이션 구조는 수정하지 않는다.

**수정 이유**

여행 상품 비교 화면은 사용자가 동일한 기준으로 여러 상품을 빠르게 비교하는 것이 핵심이므로 카드마다 정보 순서와 이미지 비율을 통일하였다. 가격의 기준도 “1인 기준”으로 명확하게 표시하여 정보 해석 오류를 줄였다.

#### 3-3. 최종 선택 이유

세 상품이 동일한 카드 시스템 안에서 일정, 항공, 숙박, 평점, 가격으로 비교되며 ‘인기/추천’ 배지로 추가적인 선택 단서를 제공한다. 검색 화면 자체가 상품 비교 페이지 역할을 충분히 수행하므로 최종 디자인으로 채택하였다.

우측에는 흰색 화살표 아이콘을 넣는다.

**초안 문제점 분석**

- 대표 이미지와 정보 카드의 연결이 자연스럽지 않으면 화면이 두 개의 독립된 영역처럼 보일 수 있음.
- 항공·호텔 정보가 길어지면서 텍스트 줄바꿈이 발생할 수 있음.
- 상세 페이지에서는 검색 결과보다 가격과 예약 CTA를 더 강하게 보여줄 필요가 있음.
- 여행 일정의 항공사 정보가 검색 결과 화면과 달라질 경우 사용자에게 혼란을 줄 수 있음.

#### 3-2. 수정 프롬프트

**수정 이미지 프롬프트**

기존 여행 상세 화면을 유지하면서 다음 사항을 수정한다.

1. 대표 이미지 하단과 화이트 상세 정보 카드가 자연스럽게 겹쳐 이어지는 구조로 만든다.
2. 상세 카드 상단 모서리를 크게 라운드 처리한다.
3. 여행 일정, 항공, 호텔 세 영역을 얇은 구분선으로 명확히 나눈다.
4. 각 영역의 좌측에는 연한 블루 배경의 둥근 아이콘 박스를 배치한다.
5. “799,000원”을 가장 크고 굵은 네이비 텍스트로 표시한다.
6. “예약 진행하기” 버튼은 화면 너비 대부분을 차지하도록 하고 코랄색을 유지한다.
7. 항공사·호텔·날짜·가격 등 텍스트가 깨지거나 임의로 변경되지 않도록 한다.
8. 다른 디자인 요소는 수정하지 않는다.

**수정 이유**

상세 화면의 핵심은 사용자가 선택한 상품을 최종 검토하고 예약으로 이동하는 것이다. 따라서 대표 이미지 → 일정/항공/호텔 → 가격 → 예약 CTA 순으로 자연스럽게 시선이 이동하도록 정보 위계를 재정리하였다.

#### 3-3. 최종 프롬프트

**최종 선택 이유**

최종 화면은 도쿄 여행의 분위기를 전달하는 대표 이미지와 실제 예약 판단에 필요한 일정·항공·호텔·가격 정보를 한 화면에 집중시켰다. 검색 결과 화면과 동일한 디자인 언어를 유지하면서 상세 화면에서는 상품 가격과 “예약 진행하기” 버튼을 더 강하게 강조해 사용자 흐름이 명확하다.

| Hotspot 적용 권장 영역 | 검색 결과 상품 카드, 각 “예약하기” 버튼, 상세 페이지 뒤로가기, 찜 아이콘, “예약 진행하기” 버튼, 하단 네비게이션 |

### 화면 흐름 다이어그램

```text
여행지 검색
     │
     ├── 항공권 / 호텔 / 명소 필터
     │
     ▼
도쿄 여행 상품 목록
     │
     ├── 도쿄 3일
     ├── 도쿄 4일 ──(상품/예약하기 클릭)──▶ 여행 상세
     └── 도쿄 5일                              │
                                                ▼
                                         예약 진행하기
                                                │
                                                ▼
                                           예약 단계
```

### 프로토타입 동작 계획

- 검색창: 여행지 검색 인터랙션 표현
- 항공권/호텔/명소: 선택 카테고리 전환
- 여행 상품 카드: 해당 상품 상세 페이지로 이동
- 예약하기: 선택 상품의 상세 또는 예약 단계로 이동
- 뒤로가기: 검색 결과 화면으로 복귀
- 하트: 찜 상태 표현
- 예약 진행하기: 예약 플로우 다음 단계로 이동
- 하단 검색: 현재 검색 화면 활성 상태 유지
- 찜/내 여행/마이페이지: 추후 확장 가능한 내비게이션 구조

## 8. 회고 및 학습 내용

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### Q1. 프롬프트 구성 요소가 결과물에 미치는 영향은?

> 여행 예약 앱은 한 화면에 날짜, 항공사, 호텔, 평점, 가격처럼 많은 정보가 들어가기 때문에 단순히 “여행 앱 UI”라고 지시하는 것보다 각 요소의 위치와 우선순위를 구체적으로 지정하는 것이 중요했다. 특히 네이비 배경, 화이트 카드, 블루 활성 상태, 코랄 예약 버튼처럼 공통 디자인 요소를 반복해서 지정하자 화면 간 일관성을 유지하기 쉬웠다.

### Q2. AI 생성 이미지의 문제점을 어떻게 식별하고 수정했는가?

> 생성된 화면을 기능별로 나누어 검색 영역, 필터, 상품 카드, 가격, CTA, 하단 네비게이션 순서로 확인했다. 수정이 필요한 경우 전체 프롬프트를 새로 작성하기보다 “가격을 더 크게”, “카드 이미지 크기를 동일하게”, “다른 부분은 수정하지 않는다”와 같이 변경 범위를 좁혀 재지시하는 방식을 사용했다. 이를 통해 이미 잘 만들어진 영역이 함께 바뀌는 문제를 줄일 수 있었다.

### Q3. 화면 간 일관성을 유지하기 위해 사용한 방법은?

> 검색 결과 화면을 기준 디자인으로 정하고 이후 상세 화면에서도 같은 네이비·블루·화이트·코랄 컬러 시스템, 둥근 카드, 라인 아이콘, 굵은 가격 타이포그래피를 반복 사용했다. 또한 이전 결과 이미지를 다음 화면의 레퍼런스로 활용한다는 조건을 프롬프트에 포함해 별개의 앱처럼 보이지 않도록 했다.

### Q4. 기획 → 이미지 생성 → 후가공 → 프로토타입 워크플로우는?

> 먼저 여행 예약 앱의 핵심 사용자 흐름을 “여행지 검색 → 상품 비교 → 상세 확인 → 예약 진행”으로 정의했다. 이후 화면별 프롬프트를 작성해 UI 이미지를 생성하고, 정보 위계·텍스트·이미지 비율·버튼 위치를 검토했다. 문제가 발견된 부분만 재지시하여 최종 시안을 확정한 뒤 Figma Make에서 화면 간 이동을 연결해 클릭 가능한 Travel Booking Flow 프로토타입으로 구성했다.

### Q5. 이번 프로젝트에서 가장 중요하게 고려한 UX 요소는?

> 사용자가 여러 여행 상품을 빠르게 비교할 수 있도록 동일한 정보 구조를 반복한 점이다. 상품명, 일정, 항공, 호텔, 평점, 가격을 항상 같은 순서로 배치하고 예약 버튼을 별도의 코랄색으로 강조하여 탐색과 행동 영역을 구분했다. 상세 페이지에서는 같은 정보를 더 자세히 보여주되 최종적으로 가격과 예약 진행 버튼에 시선이 도달하도록 정보 흐름을 구성했다.

## 10. 최종 정리

본 프로젝트는 AI 이미지 생성과 Figma Make를 활용하여 모바일 여행 예약 서비스의 핵심 사용자 흐름을 구현한 UI/UX 프로젝트이다.

최종 핵심 흐름은 다음과 같다.

**여행지 검색 → 도쿄 여행 상품 비교 → 상품 상세 확인 → 예약 진행**

검색 화면에서는 사용자가 상품을 비교하는 데 필요한 핵심 정보를 카드 형태로 제공하고, 상세 화면에서는 선택한 여행의 일정·항공·호텔·가격을 집중적으로 확인할 수 있도록 구성하였다. 전체 화면에 동일한 네이비·블루·화이트·코랄 디자인 시스템을 적용하여 하나의 서비스처럼 연결되도록 제작하였다.
